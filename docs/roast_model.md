## Verifier-in-Loop Gate Check (per ai-engineering-loop skill)

**Result: ABSENT.**
- `decide_and_generate` (`agent.py:74-140`) runs the agent **once**, then regex-scrapes the result. There is no verify → fail → re-plan-from-planner loop.
- The three advertised loop pieces are stubs: `optimize_generation_request` (`agent.py:142-155`), `evaluate_track_quality` (`agent.py:157-163`), `analyze_cost_efficiency` (`agent.py:165-173`) all return literal constants.
- `LivePerformanceUseCase` calls `evaluate_track_quality` and would gate on `_quality_threshold = 0.7` (`usecases.py:238,480`), but the shim always returns `0.75` ≥ `0.7` → the gate **always passes**. The verification gate is a no-op.
- No structured output contract means the "verifier" has nothing reliable to check.

**Fix:** Make `evaluate_track_quality` real (compare generated clip metadata — BPM/energy/style tags — to the request; reject + replay on mismatch, capped at 3 iterations), enforce strict JSON from the agent, and delete the shims that report constant scores/costs.

## The 3 Most Dangerous Findings (Fix Before Demo/Submission)

1. 🔴 **Stubbed orchestrator capabilities (verifier-in-loop gate absent).** `optimize_generation_request`, `evaluate_track_quality`, and `analyze_cost_efficiency` (agent.py:142-173) return hardcoded constants, so the advertised reflection+quality+cost loop never runs and the quality gate always passes. This is "claiming pipeline stages that don't execute" — a demo or judge will catch it instantly.
   **Fix:** Implement a real verifier-in-loop (generate → score vs request → reject-and-replan, max 3 iters) or remove the claims and the `_quality_threshold` gate that currently passes by constant.

2. 🔴 **No model-level fallback — single `gpt-4o-mini`@CometAPI point of failure.** One client, one model, one endpoint; on error the orchestrator returns an error dict with no retry/swap (agent.py:60, 108-140). A single provider hiccup kills a live set with no graceful degradation.
   **Fix:** Add a fallback chain `gpt-4o-mini@CometAPI → gpt-4o-mini@OpenAI → deepseek-chat@DeepSeek` with bounded retries; wire the already-present `deepseek_api_key`.

3. 🔴 **Cost is unenforced and falsely reported as €0.00.** `daily_budget_eur`/`max_track_cost_eur` (config.py:20-21) are never read; `analyze_cost_efficiency` always returns `total_cost_eur=0.0`. There is no spend guard and dashboards/reports will show free generation while real Suno/LLM bills accrue.
   **Fix:** Enforce `max_track_cost_eur` per `generate_track`, track rolling `daily_spend_eur` against `daily_budget_eur`, and make cost reporting read real accumulated spend.
