# Massloop — Application-Layer Code Roast (10 Prisms vs Code)

**Scope:** Application Layer only — orchestrator (`massloop-be/app/orchestrator/`), services (`artist_memory`, `state_manager`, `reasoning_store`, `externals`, `interfaces`), controllers, and the Reflex FE (`massloop-fe/`).
**Method:** Each prism's *insight* from `docs/prism-specs/` is checked against concrete code (`file:line`). Severity graded with Chip Huyen failure-mode buckets: **Relevance / Accuracy / Safety / Latency / Cost**.
**NDA:** Massloop is OWN-IP. No client/UOP references. Findings stay local (do not push).

## TOP 3 CRITICAL FINDINGS

1. **Persistent-growth memory is dead code in the product loop (Relevance / Accuracy).**
   `artist_memory` (`learn_from_chat` L49, `build_artist_context` L132, `learn_from_approval` L114) is only reachable through `stream_router` and `artist_router` endpoints that the FE **never calls** (see `state.py` — `api_client.py` only hits `/health`, `/api/performance/*`, `/api/trial/*`, `/api/stripe/*`). Worse, the real generation path `performance_router._run_approved_generation` (L206-292) calls `_orchestrator.decide_and_generate(...)` **without `artist_brand` or `artist_id`** (L238-244) and never reads `artist_memory`. So every track is generated with **zero learned artist identity**. The Economy#46 "attention ledger" / Obstacle#66 "day-1 draft" / Client#94 "audience-gap" insights are not reflected. → *Fix: inject `artist_memory.build_artist_context(artist_id)` + `learn_from_approval` into the generation + feedback path; wire FE `artist_id` and call `/api/artist/feedback`.*

2. **No real-time control / feedback / transparency plane exists (Latency / Safety).**
   A repo-wide search for `WebSocket|websocket|@router.websocket|/ws/` returns **0 hits**. Control (#53: `set_energy`/`override_ai`/undo-redo command queue), Feedback (#57: structural-change event stream, telemetry bus, ghost-layer preview, confidence badge), and Transparency (#56: `ws://…/ai-state` push, pending-action approve/deny) require a bidir low-latency channel + a pending-action queue. None exist. The FE only polls a `stage` string every 2s (`state.py:195-342`, `STAGE_LABELS` L218-227) — generation-stage labels, not AI intent/confidence. A live-director loop is impossible. → *Fix: stand up a `WebSocket /ws/control` + `/ws/ai-state`; implement pending-action queue with approve/deny and ghost-layer timeline before commit.*

3. **The verify/refine loop (ai-engineering-loop) is stubbed — quality is faked (Accuracy / Cost).**
   `agent.py:optimize_generation_request` (L142-156) returns the request **unchanged**; `evaluate_track_quality` (L157-163) returns a **constant `0.75`**; `analyze_cost_efficiency` (L165-173) returns `total_cost_eur=0.0`. In `usecases._generate_track_with_quality_check` the attempt budget is **`max_attempts = 1`** (L357) and `audio_analyzer` is optional/None by default (L454), so no librosa verification gates acceptance. There is no retry and no prompt refinement. Profit#96 (stem cache + hybrid local+Suno) is absent — every track is a full paid CometAPI/Suno call (`tools.py:59-83`), bleeding margin. → *Fix: implement real optimize/evaluate, gate acceptance on `AudioAnalysisResult.quality_issues()`, add stem cache keyed by style hash, add local rhythm model for live moments.*

## CROSS-CUTTING / SECONDARY FINDINGS

- **Orchestrator hardcoded decision.** `agent.py:131` returns `"decision": "generate"` unconditionally — the agent is told to "decide" but its decision is fabricated and never used to branch. (Accuracy)
- **Orchestrator never reads memory.** `build_orchestrator_context` (`prompts.py:43-91`) only uses a passed-in `artist_brand` dict; the generation path never supplies it, and `artist_memory` is never imported by `usecases.py` or `performance_router.py`. So even the LLM orchestrator is identity-blind. (Relevance)
- **`stream_router` is never mounted.** `main.py:53-58` registers `performance_`, `profile_`, `stripe_`, `trial_`, `orchestrator_`, `artist_` routers — **`stream_router` is absent**. It is the *only* caller of `build_artist_context` (`stream_router.py:72`), so that learning path is 100% dead. (Accuracy / Relevance)
- **Double `/api` prefix bug.** `orchestrator_router` already has `prefix="/api/chat"` (`orchestrator_router.py:13`) but `main.py:57` mounts it with `prefix="/api"` → endpoint becomes `/api/api/chat/orchestrator`. The FE never calls chat, so latent. (Accuracy)
- **HITL: trigger exists, learning does not.** FE `handle_generate` *does* call `/api/performance/approve/{id}` (`state.py:265-269`) — a real human gate to *start* generation. But `approve_artist_track`/`reject_artist_track` (`state.py:43-55`) only flip a **local** boolean; they never POST to `/api/artist/feedback`. So reject/approve never feeds `learn_from_approval`. The feedback→memory loop is broken. (Relevance)
- **`reasoning_store` is per-process, TTL 300s** (`reasoning_store.py:37`) — not shared across workers, not persisted. Combined with no FE consumer, the "real-time reasoning" feature is inert. (Latency / Relevance)
- **Crowd sensing off by default.** `state_manager.py:52` `crowd_sensing_enabled: False`; `CrowdSensingPort` has no real implementation wired into generation (the live path's `crowd.get_crowd_energy()` would be a mock). Client#94 "audience-gap" insight unmet. (Relevance)

## WHAT IS PRESENT (credit where due)

- Persistent-memory *service* exists and is well-structured (`artist_memory.py`) — it just isn't wired into the loop.
- Performance queue + HITL *approve-to-generate* flow exists and is called by the FE (`performance_router.py:153-194`, `state.py:229-342`).
- Chunked audio streaming endpoint (`performance_router.py:375-423`) and MOA-style stage labels give basic progress feedback.
- Clean Architecture layering (entities/usecases/interfaces/externals) is real; ports are defined for audio/crowd/reference/voice.

**Bottom line:** The application layer implements a *request→generate→approve→stream* pipeline, but **none** of the 10 prism insights are realized in the live product. Persistent growth, real-time control/feedback/transparency, economy, profit-engine, multi-channel sensing, and mode discipline are all either absent or stubbed. The single most important fix is wiring `artist_memory` into generation + feedback so the product actually *learns the artist* (Economy#46 / Obstacle#66 / Client#94).
